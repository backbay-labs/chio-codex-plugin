The [restricted-mode contract](../RESTRICTED.md) defines the resource owner,
operator trust and disabled paths. The stock native host receives one required
Chio MCP endpoint, fixed provider relay, ignored user configuration and a fresh
read-only local workspace. Shell, delegation, arbitrary plugins/MCP servers,
browser/computer tools and hosted web search are disabled. Native `apply_patch`
remains in the catalog but its filesystem effect boundary refuses protected and
operator configuration writes. The kernel's isolated resource container owns the
promised read/write/edit/list workflow. The guest cannot recover provider/kernel
credentials, modify the private journal, mount the resource, or issue a local
precheck followed by unrestricted execution.

The [evidence collection](../acceptance/2026-09-10/static-kernel-native/README.md)
contains 825 deterministic gzip objects. `files.json` binds every object to the
original bytes and path. Exact executed driver sources, commands, installed-file
maps, native outputs, independent resource observations, failure records,
source-CI results and operator interventions are retained. Current and
predecessor archives were installed from isolated caches and compared file by
file. All 2,337 current archive regular files, 2,338 installed regular files and six
internal symlinks were verified; current and predecessor files were checked again
after all runs. The runtime imports its cold installation, with no private
sibling source overlay. Captured driver sources separately identify operator
utilities used by the tests.

The initial lifecycle command contains 13 individually passing cases. Both
SIGTERM and SIGKILL after effect retain truthful uncertainty and same-authority
fencing; the latter includes recovery of a dead owner's lock. The host-response
loss and gateway-crash cases each retain one original effect, refuse silent
redispatch, recover only from the retained completed result, and perform a later
native read. Result-substitution separately proves rejection and no ACK; that
specific driver does not perform recovery, so it is not claimed to do so.

Each actual storage case began with a completed and acknowledged native write.
The controller held a genuine SQLite lock before admission, after an effect
before receipt persistence, or after an effect before admission-result
persistence. The first caused zero new dispatches; the latter two caused one
original effect each. All three reported unknown with no delivery ACK. Repeating
the action, requesting a new action, restarting the same kernel owner and trying
again caused zero further dispatches. The original authority, configuration and
private journal remained intact. A later fence does not undo or establish
prevention of the post-effect write.

Actual expiry used the original owner-issued capability read independently from
its trusted SQLite session record. The capability signature was verified against
its embedded issuer, which differs from the receipt signer. Its real ten-second
expiry was observed without changing database rows or clocks. Receipt trust-root
and forged-record tests are in the separate shared matrix.

The first paired timing prompt prohibited every other tool. The native host
replied that it needed tool discovery and made no protected read attempt; its
completed seed write was unchanged in the independent after-failure observation.
That command correctly failed the exact-call assertion. It is retained as a
failed measurement, not a denial observation. The qualification prompt now
explicitly permits native discovery and still requires exactly one protected
call. No runtime archive changed. The rerun used a new owner/volume on port 59248,
retaining the failed owner's databases and volume on port 59247. Source CI passed
for both `e069009` and corrected `703d4b9`.

The successful timing run used one acknowledged native seed write followed by
three native/direct readonly pairs, alternating the second pair's order. Native
parent-gateway request-to-response intervals were 389.419750, 411.659708 and
458.994083 ms; corresponding warm direct MCP intervals were 28.611250, 3.195625 and
5.623334 ms. These unlike transports include different work: the native route
includes bridge verification and kernel authorization/evidence; the operator
control calls the same resource image directly through Docker stdio with a
readonly mount. The figures exclude model generation and are descriptive stage
observations, not pure plugin cost or a general latency guarantee.
