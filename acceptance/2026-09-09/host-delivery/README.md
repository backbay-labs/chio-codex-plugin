# Host delivery qualification

Status: candidate, I01-I08 acceptance remains open.

The cold-installed package completed write/edit/read/list through the actual
Codex host and OpenAI provider. The independent resource observer recorded four
matching dispatches. Secret read and forbidden write produced verified denial
with zero resource dispatches. Native apply_patch could not modify operator
configuration or the protected resource path. Wrong resource owner refused
before host launch. The launcher confirmed four actual host deliveries.

The response-loss run kept the installed host and package unchanged. A trusted
launcher preload dropped the completed HTTP response before host delivery.
Exactly one write occurred; Codex reported unknown and exited 2. Restart using
the same authority could not dispatch a replacement. The operator exported and
read the exact retained outcome, then explicitly acknowledged it without a
resource call. A subsequent real Codex host read succeeded and left file bytes
unchanged. This does not close every interruption or recovery case in I07.

The initial malformed MCP capability candidate and a test-driver directory
collision are retained separately as failures with no resource dispatches.
Raw host events, launch reports, resource/audit observations and immutable
identities are retained here. No skipped case was treated as a pass.

Reproduce with scripts/qualify-http-host.py against a dedicated resource owner
and the installed package. Use --cases host-response-loss and --fault-injector
pointing to ARC scripts/acceptance/drop-host-response.mjs for the loss sequence.
This preload is test-only and must not be used for ordinary operation.

Remaining work includes final aggregate budget, approvals, revocation,
cancellation, complete failure matrix and published compatible installation.
